# v2 results

Every graded receipt behind the tables in the README and `RESULTS.md`, and
how each was produced. The edition these worlds belong to (`--v2`):
shared-vocabulary subjects, a fourth crossed phrasing, natural-null
controls beside the phantoms, three contradiction shapes aimed at token
differencing, answer-readable credit, capability flags, the additive
score, and the **path-shaped read**: every file the world's code refs
name is asked once, by path, through `recall_path`, the way an edit hook
asks (`docs/families.md`, `docs/protocol.md`). Worlds under `worlds/v2/`:
100, 500 and 1500 tested facts at seed 1, and 500 at seeds 2 and 3,
regenerated byte for byte by a golden test.
The seven in-process arms and the five external adapters have run the
official ladder (500 and 1500, seed 1); the in-process arms also the three
seeds at 500.

## The path read

Every note in a world carries zero to three code refs of the shape
`src/<component>/<file>.rs`; 63–64 distinct files exist at every size, and
a file binds 2–15 live notes at 500 and 8–53 at 1500. Each file is asked
once, as a path, with no question around it: *pass* is a bound note
readable in the top five, `path_cover` the share of the bound notes the
top-k delivered. Three kinds of system show up:

- **A file channel.** engram's code-ref match (the file-read hook's own
  lookup), grep's substring match over the note files, and MemContinuum's
  `for-path` answer every file and cover 0.87–1.00 of what is bound.
- **A vector store handed a path.** `rag`, LangMem, Mem0 and cognee embed
  the path string and find the *component's* notes — enough for 0.56–0.68
  of files to show one bound note in the top five, never enough to cover
  the file (0.18–0.36). Supermemory does the same behind a similarity
  floor of 0.6, and a path is not similar to much: 0.43 / 0.18 at 500,
  0.53 / 0.14 at 1500, against 0.68 / 0.34 with the floor off.
- **Titles only.** tfidf tokenises the path and matches the component
  words; its short snippets never carry the refs (0.08–0.44).

The read is 63 of 3,042 tasks at 500 and 64 of 9,008 at 1500, so it moves
no headline by more than a point; it is a column, and it is the column
MemContinuum's author asked for (below).

## The TF-IDF arm

The lexical arm — TF-IDF over the titles, one short snippet per answer —
scores **574 at 43%** at 500 and 580 at 43% at 1500, the second row of the
ladder and 227–242 points under the reference system. It is the arm the
additive score was shaped around: under a multiplied score a system that
answers in a few tokens can earn up to ten times its composite, and this
one did (`docs/scoring.md`). What it earns here is honest — 100 token
points (140 tokens per answer) and 41 signal points, plus the families it
attempts: temporal, deletion, a fair share of drift. Each mechanism it
rides, and each it lacks, is visible in a column:

- `phantom_fp` 1.00 and `natural_fp` 1.00: an idf oracle is no abstention
  rule when every word of a never-written subject was written somewhere;
- `crossed_r@5` 0.00 and `oblique_r@5` 0.05: a title index needs the
  note's own words;
- `stale_above` 0.70: the stale sibling's shorter title wins cosine;
- `path_r@5` 0.21: a path read is out of reach for an index of titles;
- contradiction 59%: token differencing catches `value` and `unit` flips
  (tier-1 recall 0.38) and nothing reworded; the `synonym` negative is
  not flagged, which is the trap working both ways.

That is where the additive score puts a lexical system: above the flat
stores that show ten whole notes, well under a memory that knows what it
knows.

## The reference system

Engram Alpha 0.9.6 is the reference row: 816 (813–818) at 500, 801 at
1500. Three columns say where it stands and where it does not:

1. **`crossed_r@5` 0.02** (rag 0.17): a question sharing no content word
   with its note is where a hybrid ranker lands under pure cosine — a
   cross-encoder has nothing to bind a described component to a named one.
2. **`hedge` 0.35–0.40**: the calibrated "not in memory" line declines
   about a third of answerable questions, which the signal score counts as
   zero — the signal score is 32–36 where the retrieval focus alone would
   give about 60. Oblique answers and natural nulls score alike on the top
   hit, so a lower line would answer controls faster than it stopped
   hedging.
3. **Contradiction 70% and drift 91–93%**: tier-1 recall 0.75–0.85, tier-2
   0.52–0.58, tier-3 0.04–0.12, and the `historical` trap costs a 0.05–0.06
   false alarm — the documented ceiling of an encoder-only logic layer.

The path read adds nothing new about it: the code-ref match is the
mechanism the file-read hook already runs, and it answers every file
(1.00 / 0.99).

**MemContinuum, before and after the revision.** Its author's reply to the
first measurement made two claims: that the 2% rationale measured the wrong
channel (the agent reads `for-path`/`chain`, which deliver the whole
record with its edges, not `search`'s 200-character snippet), and that
the system's job is to deliver every record bound to a file, unranked,
for the agent to judge. Both are now measured. Rationale went from 4% to
**100%** — every one of it is `structure_only` (0.95): the reason arrives
as the anchor's edge-neighbour, never in the top five itself, which is
exactly the chain doing the work the author described. The path read is
1.00 / 0.95 at 500 and 1.00 / 0.87 at 1500 through `for-path`. The score
moved from 295 to **392** at 500 and 287 to **380** at 1500 — one family,
one hundred points, as the additive score prices it. What did not move
is the snippet: the first number was a ranking miss, not a truncation
(`readable` never failed a MemContinuum hit), and the columns the author
did not dispute are where they were — `stale_above` 0.62 (the widest of
any system: its FTS5 channel prefers the sibling's shorter title),
abstention 0%, no suspect queue, no clock, oblique 0.31, crossed 0.05.
The unranked delivery is billed as it is used: 852 tokens a query, 46
token points, the only external bonus worth having.

Reading the rest: LangMem is `rag` to the digit again (376 and 359
against 376 and 359) — a flat store with this embedder is one system.
Every flat store answers every natural null and every phantom
(`natural_fp` and `phantom_fp` 1.00 for all four), finds the crossed
question at r@5 0.17 (LangMem), 0.06 (Mem0), 0.05 (MemContinuum), 0.17
(cognee), and puts the stale sibling above the truth on 0.27 / 0.30 /
0.62 / 0.26 of polluted questions. cognee is `rag` minus the clock again,
281, temporal N/A.

**Supermemory local 0.0.8** (`adapters/supermemory.md`) is the
self-hosted `supermemory-server` binary with its language model left out:
notes are written straight into the memory graph (`POST /v4/memories`),
never through the document pipeline, and a tripwire standing in for the
LLM provider recorded 0 calls on every receipt. Without the model it is
a vector store with two mechanisms of its own. Its search drops every
candidate under a default similarity of 0.6, which empties 3.5% / 2.0%
of recalls and trims another 17% / 7%: `phantom_fp` 0.96 / 0.98 (the
first external store under 1.00; `natural_fp` stays 1.00), retrieval two
and one points under `rag`, the smallest bill of the whole-note stores.
The ablation with the floor off (`*-threshold0.*`) scores 378 / 361 —
the same family points, a longer answer, `rag` within two points. And
its update is a version, not an overwrite: `history: true`, `lineage`
1.00 on every walk (25 and 75), `pollution` 0.00, currency 96% / 85%.
Everything else is a flat store's: no suspect queue, no edges a caller
can write (rationale 4%), a forget that keeps its reason where nothing
reads it (`trace: false`, `resurrection_warned` 0.00). Its search also
parses dates out of the question without any model: the 8 / 20 questions
containing "yesterday's" come back empty at any threshold.
